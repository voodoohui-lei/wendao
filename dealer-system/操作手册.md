## 一、数据表搭建

数据库：**SQLite**（单文件 `data/app.db`，开启 WAL 模式支持高并发读）。
表结构在 `lib/db.js` 中定义，**首次启动自动建表，无需手工执行任何 SQL**。

### 1. performance —— 业绩台账（核心表）

Excel 的 12 个固定字段一一落库，额外增加 4 个系统字段：

| 字段 | 类型 | 对应 Excel | 说明 |
|---|---|---|---|
| user_id | TEXT | 用户ID | 门店代理 ID |
| nickname | TEXT | 昵称 | |
| name | TEXT | 姓名 | |
| agent_level | TEXT | 代理等级 | |
| period | TEXT | 业绩周期 | 统一规范化为 `YYYY-MM-DD` |
| senior_id | TEXT | 归属高级ID | |
| senior_nickname | TEXT | 归属高级昵称 | |
| senior_name | TEXT | 归属高级姓名 | |
| **phone** | TEXT | 电话 | **数据隔离主键**。#N/A / 空 / 格式错误统一存空串 |
| phone_raw | TEXT | — | 保留原始文本（如 `#N/A`），供后台排查 |
| senior_level | TEXT | 归属高级等级 | |
| amount | REAL | 金额 | 空值按 0 |
| commission | REAL | 佣金 | 空值按 0 |
| row_hash | TEXT | — | 行指纹（唯一索引），**重复导入自动去重** |
| batch_id | INTEGER | — | 所属导入批次，支持整批撤销 |
| created_at | TEXT | — | 入库时间 |

索引：`phone`、`period`、`(phone, period)`、`batch_id`、`user_id`
→ 经销商查询走 `phone` 索引，几百人并发无压力。

### 2. dealer —— 经销商账号

| 字段 | 说明 |
|---|---|
| phone | 手机号，唯一 |
| password_hash / salt | **scrypt 加盐哈希**，明文密码不落库 |
| display_name | 自动取业绩表中的归属高级姓名 |
| status | `active` 启用 / `disabled` 停用 |
| created_at / last_login_at / login_count | 注册与登录轨迹 |

### 3. admin —— 管理员

初始账号 `admin` / `admin888`，`must_change=1` 会在首次登录强制弹出改密。

### 4. session —— 服务端会话

Token 存服务端，浏览器只持 HttpOnly Cookie（JS 读不到），有效期 12 小时，过期自动清理。

### 5. import_batch —— 导入批次

记录每次导入的文件名、模式、总行数、入库数、跳过重复数、#N/A 数、操作人。**支持一键撤销整批**。

### 6. audit_log —— 审计日志

登录、注册、导入、导出、改密、停用账号等全部留痕，含 IP。

## 三、权限矩阵

| 能力 | 未登录 | 经销商 | 管理员 |
|---|:---:|:---:|:---:|
| 查看任何业绩数据 | ✗ | 仅自己名下 | 全部 |
| 查看他人业绩 | ✗ | **✗ 服务端强制拦截** | ✓ |
| 查看 #N/A 无手机号数据 | ✗ | **✗** | ✓ |
| 查看他人手机号 / 上级信息 | ✗ | **✗ 字段不下发** | ✓ |
| 批量查看全量台账 | ✗ | **✗** | ✓ |
| 导出数据 | ✗ | 仅本人明细 | 全量 CSV |
| Excel 导入 | ✗ | ✗ | ✓ |
| 账号管理 | ✗ | ✗ | ✓ |
| 注册 | 需手机号在业绩表内 | — | — |

### 隔离是怎么做到的（不是靠前端藏）

1. 经销商所有数据接口，SQL 里 `WHERE phone = ?` 的参数**只从服务端 Session 取**，前端传的 `phone` 参数被完全忽略。
   → 实测：A 构造 `?phone=B的手机号` 请求，返回的仍是 A 自己的 51 条。
2. 经销商明细接口**不下发** `phone`、`senior_id`、`senior_name` 等字段，抓包也拿不到别人信息。
3. 管理员与经销商用**不同 Cookie、不同路由前缀**，权限不继承。经销商访问任何 `/api/admin/*` 一律 401。
4. 登录限流：同一 IP+手机号 10 分钟内 8 次失败即锁定；注册 10 分钟 10 次。

## 五、Excel 导入全套操作步骤

### 方式 A：后台上传（日常用）

1. 登录 `/admin` → 点「Excel 导入」
2. 拖入 `.xlsx` 或点击选择（也支持 `.csv`，上限 30MB）
3. **系统自动解析并给出预览**：有效行数、涉及手机号数、#N/A 行数、金额/佣金合计、业绩周期
   - 表头缺列会直接报错并指出缺哪一列
   - 无效行（用户ID 或周期为空）会跳过并列出行号
4. 选择导入模式：

   | 模式 | 行为 | 什么时候用 |
   |---|---|---|
   | **追加导入**（默认） | 新增数据，完全重复的行自动跳过 | 每月新增一个周期的数据 |
   | **按周期覆盖** | 先删掉文件中出现周期的全部旧数据，再导入 | 上月数据导错了要重来 |

5. 点「确认导入」→ 显示「新增入库 X 行，跳过重复 Y 行」
6. 到「数据概览」核对总额是否与 Excel 一致

### 方式 B：命令行（首次初始化 / 定时任务）

```bash
node tools/import-cli.js "D:\温道\workbuddy\经销商业绩统计表\业绩统计-46204-门店代理.xlsx"

# 按周期覆盖
node tools/import-cli.js "路径\文件.xlsx" --replace
```

### 每月更新的标准流程

1. 从商城导出当月业绩 Excel（保持 12 个字段不变）
2. **务必在 Excel 里把 VLOOKUP 等公式列转成数值**（选中 → 复制 → 选择性粘贴为「值」）
   > 本次源文件就出现过公式未刷新导致电话显示 `#N/A` 的情况，重算保存后才变成真实号码
3. 后台上传 → 预览确认「涉及手机号数」和「金额合计」符合预期 → 追加导入
4. 万一导错：到「导入记录」点「撤销本次」，整批干净回滚

### 字段兼容说明

- 列顺序可任意；列名允许小差异（如「手机号」≈「电话」，「提成」≈「佣金」）
- 业绩周期支持：`2026-07-01`、`2026/7/1`、`2026年7月`、Excel 日期格式
- 电话为 `#N/A`、空、格式错误 → 记为「无手机号数据」，**仅后台可见，经销商端永不出现**
- 金额/佣金为空按 0 计
- 同一文件重复上传不会产生重复数据（行指纹去重）

## 七、上线部署（数百人访问）

本地跑通后，要让 99 个经销商随时能访问，需要一台**有公网 IP 的服务器**。

### 推荐配置
腾讯云/阿里云轻量应用服务器，**2 核 2G 足够**（605 行数据、300 并发实测平均 1.7ms）。

### 部署步骤（Linux）

```bash
# 1. 装 Node（Ubuntu 示例）
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

# 2. 上传整个 dealer-system 目录到 /opt/dealer-system
#    （用 scp / 宝塔面板 / FinalShell 都行）

# 3. 试跑
cd /opt/dealer-system && node server.js

# 4. 配置开机自启（systemd）
sudo tee /etc/systemd/system/dealer.service <<'EOF'
[Unit]
Description=Dealer Performance System
After=network.target
[Service]
WorkingDirectory=/opt/dealer-system
ExecStart=/usr/bin/node server.js
Environment=PORT=8080
Restart=always
User=root
[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now dealer
sudo systemctl status dealer
```

### 必做两件事

1. **开放安全组端口**（云控制台放行 8080，或用 Nginx 反代到 80/443）
2. **配 HTTPS**（强烈建议，微信里打开 http 会提示不安全）
   - 最省事：宝塔面板 → 网站 → 反向代理到 `127.0.0.1:8080` → 申请免费 SSL
   - 配好 HTTPS 后，在 `lib/auth.js` 把 `setCookie(res, role, token, false)` 的 `false` 改为 `true`（启用 Secure Cookie）

### Nginx 反代示例

```nginx
server {
    listen 80;
    server_name yeji.你的域名.com;
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

> `X-Forwarded-For` 必须带上，否则审计日志和限流拿不到真实 IP。

## 八、日常运维

### 备份（重要）

所有数据就在 `data/` 目录，**直接复制走就是完整备份**：

```bash
# Windows
copy data\app.db D:\备份\app_%date%.db

# Linux（建议加到 crontab 每天凌晨跑）
cp /opt/dealer-system/data/app.db /backup/app_$(date +\%F).db
```

恢复：停服务 → 用备份文件覆盖 `data/app.db` → 启动。

> 提示：WAL 模式下同目录会有 `app.db-wal`、`app.db-shm`，**冷备份时三个一起复制**最稳妥。

### 常见问题

| 现象 | 处理 |
|---|---|
| 经销商说「手机号不在名单中」 | 后台「账号管理」搜该号码；不在列表说明 Excel 里没有，或是门店代理本人号而非归属高级号 |
| 经销商忘记密码 | 后台「账号管理」→「重置密码」→ 把生成的临时密码告知本人 |
| 想让某人重新注册 | 「删除账号」，业绩数据保留，对方可用同号重新注册 |
| 导入后数字对不上 | 检查 Excel 是否有公式未转数值；或用「按周期覆盖」重导 |
| 端口被占用 | `set PORT=9000` 换端口启动 |
| 忘记管理员密码 | 停服务，删除 `data/app.db` 中 admin 表记录后重启会重建默认管理员（会丢失管理员配置，业绩数据不受影响） |

### 性能参考（本机实测）

| 场景 | 结果 |
|---|---|
| 605 行 Excel 解析 | 26 ms |
| 300 个并发经销商查询 | 总 513 ms，平均 1.7 ms/请求 |
| 100 个并发后台全量查询 | 173 ms |

数据量到 10 万行、并发到 500 人仍在 SQLite 舒适区，无需换数据库。

## 九、安全边界（请知悉）

- ✅ 密码 scrypt 加盐哈希，服务端不存明文，管理员也看不到用户密码
- ✅ 行级隔离在 SQL 层强制，不依赖前端，抓包/改参数均无效
- ✅ Session 存服务端，Cookie 为 HttpOnly，JS 无法窃取
- ⚠️ **部署到公网后，链接任何人都能打开**（但没有账号看不到任何数据）
- ⚠️ 未配 HTTPS 前，密码在传输中是明文，**上线务必配证书**
- ⚠️ 系统无短信验证码，注册只校验「手机号是否在业绩表内」。若担心他人冒用同事手机号抢注，可让经销商上线首日集中完成注册，之后在后台核对注册名单
